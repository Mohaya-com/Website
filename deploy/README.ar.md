# دليل نشر نظام إدارة الزوار (خطوة بخطوة)

هذا الدليل ينقلك من الكود إلى **رابط عام آمن (HTTPS)** يعمل عليه الموقع والتطبيق، على خادم واحد باستخدام Docker. كل ما ستشغّله موجود في مجلد `deploy/`:

| الملف | وظيفته |
|---|---|
| `docker-compose.yml` | يشغّل قاعدة البيانات PostgreSQL، والنظام، وخادم Caddy الذي يصدر شهادة HTTPS تلقائيًا، ونسخًا احتياطيًا يوميًا |
| `.env.example` | قالب الإعدادات: انسخه إلى `.env` واملأه |
| `Caddyfile` | إعداد HTTPS والتوجيه إلى النظام |

> تم اختبار هذه الحزمة كاملة على بيئة تجريبية: بناء الصورة، وتطبيق الجداول تلقائيًا، وشهادة HTTPS، وتسجيل الدخول، والتحديث المباشر، والنسخة الاحتياطية. يبقى تنفيذها على خادمك الفعلي بالخطوات أدناه.

---

## 1) ما تحتاجه قبل البدء

1. **خادم (VPS)** بنظام Ubuntu 24.04. المواصفات المقترحة: معالجان، وذاكرة 4 جيجابايت، وتخزين 40 جيجابايت. يمكن استخدام أي مزوّد، مثل Hetzner أو DigitalOcean أو AWS Lightsail، أو مزوّد سحابي محلي.
2. **نطاق (Domain)**، مثل `vms.example.com`.
3. **بريد إلكتروني** يُستخدم لإشعارات شهادة HTTPS.
4. (لاحقًا) حساب مزوّد رسائل SMS لإرسال رموز التحقق للزوار. يمكن تشغيل النظام بدونه في البداية، وسيسجّل أمن البوابة الزوار يدويًا.

## 2) ربط النطاق بالخادم

في لوحة تحكم النطاق، أضف سجل **A** يشير إلى عنوان IP الخادم:

```
النوع: A    الاسم: vms    القيمة: <IP الخادم>
```

انتظر حتى يعمل السجل، فقد يستغرق ذلك دقائق. للتحقق: `ping vms.example.com` يجب أن يُظهر عنوان خادمك.

## 3) تجهيز الخادم (مرة واحدة)

اتصل بالخادم عبر SSH ثم نفّذ:

```bash
# تثبيت Docker
curl -fsSL https://get.docker.com | sh

# جدار الحماية: SSH و HTTP و HTTPS فقط
sudo ufw allow 22/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp && sudo ufw allow 443/udp
sudo ufw --force enable

# تنزيل الكود
git clone https://github.com/Mohaya-com/Website.git
cd Website/deploy
```

## 4) الإعدادات

```bash
cp .env.example .env
openssl rand -base64 48   # نفّذ الأمر ثلاث مرات وانسخ كل ناتج إلى خانة مختلفة
nano .env
```

املأ القيم التالية على الأقل:

| المتغير | القيمة |
|---|---|
| `DOMAIN` | نطاقك بدون `https://`، مثل `vms.example.com` |
| `ACME_EMAIL` | بريدك الإلكتروني |
| `POSTGRES_PASSWORD` | كلمة مرور طويلة عشوائية (الناتج الأول) |
| `PASS_TOKEN_SECRET` | مفتاح سري (الناتج الثاني) |
| `OTP_SECRET` | مفتاح سري مختلف (الناتج الثالث) |
| `SMS_PROVIDER` | اتركه `disabled` حتى تجهّز مزوّد الرسائل (انظر الخطوة 8) |

> ⚠️ لا تشارك ملف `.env` ولا ترفعه إلى GitHub. الملف مستثنى من Git تلقائيًا. احتفظ بنسخة منه في مكان آمن.

## 5) التشغيل

```bash
docker compose up -d --build
```

- يستغرق البناء أول مرة بين 5 و10 دقائق.
- يُنشئ النظام جداول قاعدة البيانات تلقائيًا عند كل تشغيل، ويطبّق أي تحديثات جديدة عليها.
- يصدر Caddy شهادة HTTPS تلقائيًا خلال دقيقة تقريبًا.

للتحقق:

```bash
docker compose ps                 # يجب أن تكون الخدمات تعمل، والنظام (web) بحالة healthy
curl https://vms.example.com/api/v1/health
```

افتح `https://vms.example.com`. هذا هو **الرابط العام**.

## 6) إنشاء أول مدير للنظام

```bash
docker compose exec web docker-entrypoint.sh create-admin --username admin --name "اسم المدير"
```

سيطلب منك الأمر كلمة المرور مرتين: 10 أحرف على الأقل، تتضمن حروفًا وأرقامًا. ثم سجّل الدخول من `https://vms.example.com/login`.

> لا تشغّل أمر البيانات التجريبية (`db:seed`) على الخادم الفعلي. وهو يرفض العمل في وضع الإنتاج أصلًا.

## 7) الإعداد الأولي داخل النظام

بعد تسجيل الدخول كمدير:

1. **إعدادات النظام**: اسم المجمع بالعربية والإنجليزية، ومدة الزيارة الافتراضية والقصوى، ونافذة الدخول، ومهلة التأخر.
2. **الفلل**: أضف أرقام الفلل.
3. **البوابات**: أضف بوابات المجمع، ثم اضغط «طباعة الرموز» واطبع لوحتي «دخول» و«خروج» لكل بوابة وثبّتهما عندها.
4. **الموظفون**: أنشئ حسابات أمن البوابة. تظهر كلمة مرور مؤقتة مرة واحدة فقط، ويُطلب من الموظف تغييرها عند أول دخول.

## 8) رسائل التحقق للزوار (SMS)

ما دام `SMS_PROVIDER=disabled`، يسجّل أمن البوابة الزوار من شاشة «تسجيل زائر»، ويرى الزائر رسالة توجّهه إلى البوابة.

لتفعيل التسجيل الذاتي برمز التحقق عبر **Twilio**:

```bash
nano .env
# SMS_PROVIDER=twilio
# TWILIO_ACCOUNT_SID=...   TWILIO_AUTH_TOKEN=...
# TWILIO_FROM=+1...   أو   TWILIO_MESSAGING_SERVICE_SID=MG...
docker compose up -d
```

ملاحظات:

- قد يتطلب إرسال الرسائل إلى الأرقام السعودية تسجيل **اسم المرسل (Sender ID)** وفق متطلبات هيئة الاتصالات والفضاء والتقنية. راجع ذلك مع مزوّد الرسائل.
- إذا فضّلت مزوّدًا محليًا، أخبرني باسمه وأضيف دعمه. يكفي تنفيذ واجهة واحدة في `packages/server/src/providers/sms.ts`.
- جرّب بعد التفعيل: افتح `https://vms.example.com/visitor`، وأدخل رقم هوية ورقم جوالك، وتأكد من وصول الرمز.

## 9) تطبيق الجوال (iOS و Android)

التطبيق يتصل بنفس الخادم، فلا يحتاج إلا معرفة رابطك.

### أ) تجربة سريعة على جوالك بدون متاجر (Expo Go)

على جهازك (وليس على الخادم):

```bash
git clone https://github.com/Mohaya-com/Website.git && cd Website
corepack enable && pnpm install
echo "EXPO_PUBLIC_API_URL=https://vms.example.com" > apps/mobile/.env
pnpm dev:mobile
```

ثبّت تطبيق **Expo Go** على الجوال، وامسح رمز QR الظاهر في الطرفية.

### ب) بناء التطبيق للمتاجر (EAS)

1. أنشئ حسابًا مجانيًا على expo.dev.
2. عدّل في `apps/mobile/eas.json` قيمة `EXPO_PUBLIC_API_URL` في قسم `production` إلى رابطك.
3. نفّذ:

```bash
npm i -g eas-cli
cd apps/mobile
eas login
eas init                                          # ضع المعرّف الناتج في EAS_PROJECT_ID
eas build --profile preview --platform android    # ملف APK للتثبيت المباشر على أجهزة أندرويد للتجربة
eas build --profile production --platform all     # نسخ المتاجر
eas submit --profile production --platform all    # الرفع إلى App Store و Google Play
```

متطلبات المتاجر:

- **Apple Developer Program**، باشتراك سنوي، للنشر على App Store.
- **Google Play Console**، برسوم تسجيل لمرة واحدة.
- سياسة خصوصية منشورة: يمكنك استخدام صفحة `https://vms.example.com/privacy` بعد مراجعة نصّها.

### ج) الإشعارات الفورية (اختياري)

بعد `eas init`:

1. ضع `PUSH_PROVIDER=expo` في ملف `deploy/.env`، ثم نفّذ `docker compose up -d`.
2. ابنِ التطبيق من جديد عبر EAS.

الإشعارات داخل التطبيق تعمل دائمًا، حتى بدون هذه الخطوة.

## 10) التحديثات والصيانة

```bash
cd ~/Website && git pull && cd deploy && docker compose up -d --build   # تحديث النظام (الجداول تتحدّث تلقائيًا)
docker compose logs -f web                                              # متابعة السجلات
docker compose restart web                                              # إعادة تشغيل النظام
```

### النسخ الاحتياطي

- تُحفظ نسخة كل يوم في `deploy/backups/`، وتُحذف النسخ الأقدم من `BACKUP_KEEP_DAYS` يومًا.
- **انسخ هذا المجلد دوريًا خارج الخادم**، مثل مساحة تخزين سحابية، لأن النسخة على الخادم نفسه لا تحمي من فقدانه.

الاستعادة من نسخة احتياطية:

```bash
docker compose exec -T postgres pg_restore -U vms -d vms --clean --if-exists < backups/vms-YYYYMMDD-HHMMSS.dump
docker compose restart web
```

## 11) حل المشكلات الشائعة

| المشكلة | الحل |
|---|---|
| المتصفح لا يفتح الرابط أو يعرض خطأ شهادة | تأكد أن سجل A يشير إلى الخادم، وأن المنفذين 80 و443 مفتوحان، ثم راجع `docker compose logs caddy` |
| النظام (web) لا يعمل وتظهر `Invalid server configuration` | راجع القيم المذكورة في رسالة الخطأ داخل `.env`. المفاتيح السرية يجب أن تكون 32 حرفًا على الأقل ومختلفة عن بعضها |
| نسيت كلمة مرور المدير | أنشئ مديرًا جديدًا بالأمر في الخطوة 6 باسم مستخدم مختلف، ثم أعد تعيين كلمة المرور من «الموظفون» |
| التطبيق لا يتصل بالخادم | تأكد أن `EXPO_PUBLIC_API_URL` هو رابطك الكامل بـ `https://`، وأن الموقع يفتح من متصفح الجوال |

## قائمة تحقق قبل الإطلاق

- [ ] الرابط يعمل عبر HTTPS، والصفحة `/api/v1/health` تُظهر `ok: true`
- [ ] تم إنشاء المدير الأول، وحذف `SETUP_TOKEN` إن كان مستخدمًا
- [ ] أُدخلت الفلل والبوابات الحقيقية، وطُبعت لوحات QR وثُبّتت
- [ ] أُنشئت حسابات أمن البوابة وجُرّب مسح تصريح فعلي عند البوابة
- [ ] جُرّب إرسال رمز التحقق بالرسائل النصية (إن كان مفعّلًا)
- [ ] النسخ الاحتياطية تُنسخ خارج الخادم
- [ ] روجع نص إشعار الخصوصية ومدة الاحتفاظ بالبيانات مع المختصين
